# Contributing

Report unclear setup, broken links or coaching failures using fictional/redacted
examples. Include guide, profile, package version, provider/interface, input, actual
behavior and expected behavior. Never post private learner work, secrets or account
receipts. Public issues are public; email help@bigleverinstitute.org if appropriate.

Edit source templates/profiles/curriculum, not generated packages. Curriculum fixes
for the BLI default should first be reconciled with the curriculum-only repository.
Run the tests and source-fidelity verifier, review consequential changes and rerun
failing cases before submitting a small PR. Describe observed evidence and limits.

By submitting your original contribution, you agree that it can be distributed under
the license applying to the file you changed. Do not submit work you lack permission
to share, or change separately licensed curriculum to the kit's narrower license.
Mark substantive adaptations and retain attribution. Contributions are not automatically
accepted into the Institute's curriculum or published to students.

## Commit attribution

Use your GitHub-provided `noreply` address for author, committer and co-author
attribution. CI checks all reachable commits and rejects other email addresses
without echoing them in logs. Keep private conversations and working notes out of
files, commit messages, issues and pull requests.
